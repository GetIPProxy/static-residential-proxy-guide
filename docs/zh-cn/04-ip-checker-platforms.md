# 检测平台全景：同一个 IP 为什么各站结果不同，以谁为准

> **适合谁读**：用过两个以上检测站、被互相矛盾的结论搞糊涂的人；准备建立自己 IP 检测流程的采购和运营人员
> **读完你能**：知道主流检测平台各自回答什么问题；理解结果不一致的原因；用"交叉验证 + 红黄绿灯"给一个 IP 下结论
> **阅读时间**：约 18 分钟
> **系列位置**：第 04 篇 · 主线的"工具"部分，第 05–08 篇的总纲

---

## 先说结论

- 各家检测站用的数据和判断方法不同，更新的时间也不一样。同一个 IP 查出不同结果时，先看看分歧出在哪一项。
- 想知道查出来在哪儿，就看地理库。想查有没有滥用记录，就看风险分和相关字段。想分清家宽和机房，就从「IP 类型」查起。
- 查地区时，先对比几个地理库，再看你实际用的平台显示什么。查风险时，至少找两个独立来源。每次查完记下日期。
- 用本文的**红黄绿灯判定法**，可以把一堆字段快速归纳成"能用 / 看场景 / 要求更换"。

## 二、IP 数据是从哪里来的

理解数据来源，是理解"为什么结果不同"的前提。常见的来源有六类：

| 数据来源 | 通俗理解 | 主要用来判断 |
|---|---|---|
| RIR / WHOIS 注册信息 | **户籍登记**：IP 段登记在哪个组织、哪个国家名下 | 归属、注册国家、原生 / 广播 |
| BGP 路由宣告 | **门牌号挂在哪栋楼**：这个 IP 段当前由哪个网络（ASN）对外宣告 | ASN、网络归属 |
| 运营商 geofeed | **业主自己申报的住址**：网络运营者按 RFC 8805 / RFC 9632 格式公开自己 IP 段的地理位置 | 地理位置 |
| 主动延迟测量 | **实地走访**：从全球多个节点探测目标 IP，延迟最低的地方大概率就是它的位置 | 地理位置 |
| 用户与合作方回传数据 | **街坊邻居提供的线索**：网站、App、合作伙伴回传的访问数据 | 地理位置、使用者类型、共享情况 |
| 蜜罐与滥用报告 | **派出所的案底**：部署诱饵系统捕获恶意流量，以及收集公开黑名单和合作方举报 | 风险评分、滥用记录、代理识别 |

每个平台组合使用其中几类，权重各不相同。例如：

- ping0 的 IP 位置主要来自**自研的主动延迟测量**，它在说明中明确表示，实测延迟的优先级高于任何第三方 IP 库；
- IPQS 的风险评分主要来自它在 150 多个国家部署的**蜜罐和欺诈陷阱网络**；
- 很多地理库在缺少其他线索时，会**退回到注册信息**——这就是为什么跨国组织的 IP 常被定位到它的总部所在地。

## 三、为什么同一个 IP，各站结果不一样

### 原因 1：它们问的不是同一个问题

最典型的是"IP 类型"。

- 有的字段说的是网络类型。比如 ipinfo 的 ASN 类型可能显示为 `ISP`，也就是网络运营商。ASN 是自治系统编号；
- ping0 则按它对网段用途的判断，把 IP 标为「家庭宽带」或「IDC 机房」。

所以会出现：其他平台显示"双 ISP"、住宅，ping0 却显示"IDC 机房"。ping0 在说明中举过例子：运营商的 IP 被用在机房服务器上，所有者是 ISP，但实际用途是机房。

**读报告时，先看这个字段查的是什么，再对照各家给出的结果。**

### 原因 2：数据来源不同

地理位置最容易出现分歧。依赖注册信息的库、依赖 geofeed 的库、依赖延迟测量的库，对同一个 IP 可能给出不同的城市。APNIC 和运营商社区的测量研究都显示，不同地理库之间在城市级别上的分歧相当普遍，即使在国家级别也并非总是一致。

### 原因 3：更新时间不同

- 运营商发布或更新 geofeed 后，各家数据库采纳的时间可能相差数周；
- ping0 扫描一遍全网 IP 大约需要 5 天；
- 风险评分则会随新的滥用记录实时变化。

所以，**两个平台对同一个 IP 的结论不同，有时只是因为其中一个还没更新**。

### 原因 4：评分模型和量表不同

ping0 的「风控值」和 IPQS 的欺诈分（`fraud_score`）都是 0–100。读分数时，先看各家怎么分档。

| | ping0 风控值 | IPQS fraud_score |
|---|---|---|
| 主要依据 | 扫描、爆破、爬虫、对外攻击、垃圾邮件、木马 C&C 等行为的次数与频率 | 蜜罐网络观察到的欺诈与滥用信号，以及代理 / VPN 识别等 |
| 工具怎么解释低分 | ping0 的说明把 50 以内称为「安全」，15 以内是「极度纯净」，15–25 是「纯净」 | IPQS 网页把 0–39 分列为低风险 |

**两个分数不能互相换算**，也不能拿一个平台的阈值去套另一个平台。

### 原因 5：查询方式不同

同一个平台，不同的查询方式也可能得出不同结果：

- IPQS 的 API 支持 `strictness`（严格程度）等参数，官方说明较高的严格程度可能带来更多误报；还可以带上浏览器的 User-Agent 和语言一起评估。网页查询和 API 查询、不同参数的 API 查询，分数可能不同；
- 免费查询和付费查询能看到的字段也不同，付费字段在免费版里显示为"需要升级"，**这不代表没有风险，只代表你没看到**。

### 原因 6：广播 IP 的注册地和使用地不一致

按 ping0 的定义，如果这个 IP 的注册国家是 A 国，ping0 查出来是 B 国，页面就会标为「广播 IP」。有的库可能显示注册国家，有的会参考测量结果或运营商发布的地区数据。数据库更新后，显示的地区也可能变。

### 原因 7：你自己的查询方式可能影响结果

- 中文技术社区有观点认为，ping0 的部分指标（如共享人数）会参考访问者信息；如果浏览器存在 WebRTC 泄露，或者频繁用同一个出口反复查询，可能影响结果。这是社区推测，ping0 官方说明中"共享人数"是基于全网大数据的估算；
- 无论如何，**不要用自己的业务出口反复刷新查询**，查一次、截图、记录日期即可。

## 四、全球与中国主流 IP 查询网站速查

下面按用途，每类挑选 2–3 个全球或中国用户最常用的站点，说明能看什么、适合回答什么问题、有哪些局限。ping0、IPQS、Scamalytics、ipinfo 分别在第 05、06、07 篇详细讲解，这里不再重复。

> 各站点的功能、免费额度和页面会调整，以下内容核对于 2026 年 11 月，使用时以各站当前页面为准。

### 1. 出口显示类：确认"我现在用的是哪个 IP"

| 站点 | 能看什么 | 适合 | 局限 |
|---|---|---|---|
| ifconfig.me | 当前出口 IP，支持命令行（`curl ifconfig.me`） | 快速确认代理是否生效；脚本中自动记录出口 | 不提供质量判断 |
| IP.SB | 同时检测 IPv4 和 IPv6 出口，可查指定 IP 的位置和 WHOIS | 检查 IPv6 是否绕过了代理 | 不提供风险评分 |
| myip.ipip.net | 当前出口 IP 及 IPIP.NET 库中的归属 | 国内用户快速查看 | 以国内数据库视角为主 |

**用法提示**：任何检测之前，先确认出口就是你要检测的 IP，并确认 IPv6 没有绕过代理。

### 2. 地理与归属库：判断"在哪里、归谁"

| 站点 | 能看什么 | 适合 | 局限 |
|---|---|---|---|
| MaxMind（GeoIP / GeoLite） | 国家、地区、城市、ASN；付费产品有用户类型与匿名 IP 识别 | 被大量网站采用，代表"很多平台可能看到的定位" | 网页只有演示查询；官方不承诺具体准确率 |
| IP2Location / IP2Proxy | 地理、usage type（ISP、DCH 数据中心、COM 商业等）；IP2Proxy 识别代理类型，其中 RES 表示住宅代理 | 又一个主流库的定位与类型判断 | Scamalytics 的代理数据来自 IP2Proxy，两者结论相同时不算两个独立来源 |
| ip138.com | IP 归属地（国内库视角），提供网页查询和 API | 国内老牌查询站，看"国内数据库怎么定位" | 不反映海外平台的风控视角，不适合评估海外住宅 IP 的纯净度 |

**用法提示**：海外住宅 IP 的地理判断，以 MaxMind、ipinfo、IP2Location 等国际主流库的多数结论为准；ip138 这类国内库只用来回答"国内数据库怎么看这个 IP"。

### 3. 风控与代理识别：判断"干不干净、像不像普通用户"

除了 ping0、IPQS、Scamalytics，中文用户还常用以下两个站点：

| 站点 | 能看什么 | 适合 | 局限 |
|---|---|---|---|
| IPPure | 风险分数、ASN 人机流量比等 | 中文用户常用的纯净度查询站 | 官方说明：风险数据来自互联网风险数据库和蜜罐统计，分数随时间衰减，没有记录的 IP 按所在网段推断；ASN 人机流量比来自 Cloudflare 数据，只精确到 ASN；IPv6 不参与评分 |
| ipapi.is | 是否为数据中心 / 托管、代理、VPN，以及是否有滥用记录 | 重点在识别托管和机房 IP，适合复核"类型真实性" | 各标记的判定口径以官方文档为准 |

### 4. 黑名单与滥用举报：判断"有没有案底"

| 站点 | 能看什么 | 适合 | 局限 |
|---|---|---|---|
| Spamhaus（check.spamhaus.org） | 是否在 Spamhaus 的各类黑名单中 | 确认最知名的反垃圾邮件 / 恶意网络黑名单 | 只覆盖自家名单 |
| MXToolbox Blacklist Check | 一次查询 100 多个公开黑名单（DNSBL） | 快速扫一遍主要黑名单 | 主要面向邮件发送场景；不在黑名单不等于信誉好 |
| AbuseIPDB | 用户举报记录与 0–100 的滥用置信度 | 看这个 IP 是否被他人举报过扫描、攻击等行为 | 基于众包举报，分数要结合举报数量和时间看 |

**用法提示**：黑名单查询和风险评分回答的是不同问题。一个 IP 可能不在任何黑名单上，但在风控评分中偏高；反之亦然。两类都要看。

### 5. 网络与路由：判断"这个 IP 段由谁宣告、历史如何"

bgp.tools、bgp.he.net（Hurricane Electric BGP Toolkit）、RIPEstat。配合 ping0 的 ASN / 企业 / 注册地历史表使用，方法见[第 08 篇](08-asn-and-isp.md)。

### 6. 多源聚合类：一次看多个数据库

| 站点 / 工具 | 能看什么 | 适合 | 局限 |
|---|---|---|---|
| iplocation.net | 同一个 IP 在多家地理库中的结果 | 快速比较地理库之间的分歧 | 各库结果的更新时间不同 |
| ip.skk.moe | 多来源的出口 IP 与归属信息，另有分流检测页面 | 中文技术用户常用于检查多出口、分流是否正确 | 结果的权威性取决于各数据源 |
| IPQuality 脚本（IP.Check.Place，开源） | 在服务器上运行，汇总 MaxMind、IPinfo、IPQS、Scamalytics、AbuseIPDB 等多个来源，并检测黑名单 | 有服务器的技术用户做一次全面"体检" | 需要在服务器上运行，不适合直接检测买来的代理出口 |

**用法提示**：聚合工具能节省时间，但展示的仍然是各数据源自己的结论。遇到分歧，按本篇第五、六部分的方法判断，而不是简单"数票数"。

### 7. 环境泄露检测：判断"真实信息有没有漏出去"

BrowserLeaks、ipleak.net、ping0 环境检测。这类工具检查的是你的浏览器和设备，而不是 IP 本身。用法见[第 11 篇](11-long-term-maintenance.md)。

### 8. 遇到不熟悉的查询站，先问三个问题

市面上的 IP 查询站很多，每年都有新站出现。使用前先确认：

1. **它的数据来自哪里**：自有数据，还是转引 MaxMind、IPQS、Scamalytics 等第三方？
2. **字段如何定义**：分数越高越好还是越差？"住宅""原生"是怎么判断的？
3. **数据多久更新**：是实时查询，还是几周前的数据库？

说不清这三件事的分数，参考价值有限。

## 五、以谁为准：按问题选平台

| 你想回答的问题 | 主要看 | 用来复核 | 最终校验 |
|---|---|---|---|
| 这个 IP 在哪个国家、哪个城市？ | MaxMind、ipinfo、IP2Location 的多数结论 | ping0 IP 位置（基于延迟测量） | 目标平台自己显示的地区 |
| 是家宽还是机房？ | ping0「IP 类型」 | IPQS `connection_type`、ipinfo 的 ASN 类型 | 如果一定要真实家宽，再问卖家出口接在哪里 |
| 原生还是广播？ | ping0 原生 IP / 广播 IP、注册地历史 | WHOIS 注册国家 | — |
| 有没有不良记录？ | ping0「风控值」或 IPQS 欺诈分（`fraud_score`） | 用另一个来源再查一次，也可以看 Scamalytics 的 `Fraud Score` 和黑名单 | 对照近期滥用和黑名单记录 |
| 有没有别人在用？ | 购买条款是否写明独享 | ping0「共享人数」、IPQS `proxy`、ipinfo / Scamalytics 住宅代理标记 | 让卖家确认是否同时分给其他客户 |
| 会不会长期稳定？ | 购买条款、ping0 的 ASN 历史、企业历史和注册地历史 | 用相同方法定期复检 | 问清楚使用期内是否固定、续费能否保留原 IP |

## 六、交叉验证四步法

**第 1 步：先确认出口是对的**
用 ip.me 或 ifconfig.me 确认当前出口就是你要检测的 IP，并排除 WebRTC、DNS 泄露（第 11 篇）。否则后面查的可能根本不是这个 IP。

**第 2 步：地理信息看"多数"**
至少对比 3 个主流地理库，先看国家是否一致。几个网站查出的城市不一样，就看看是不是同一个都市圈。业务要认到具体城市，再去你实际用的平台看一眼，确认它显示的是哪儿。

**第 3 步：类型信息看"多数 + 原因"**
先分清哪个字段在查网络类型，哪个在查网段用途。如果只有一家显示机房，再看历史表里这段地址是否刚有变化。需要确认真实家宽时，问卖家出口接在哪里。

**第 4 步：风险信息看"两个独立来源"**
先按你和卖家约定的检测站查，再用另一个来源核对风险。两个网站如果用了同一家数据商的同一项标记，只算查到了一条证据。

- 一个来源的分数落在下表的黄灯区间，另一个正常，就看你的业务能不能接受；
- **多个来源都偏高、查到近期滥用，或分数已达到你约定的红灯线**，就按购买时说好的条件要求更换。

查完把截图和日期一起存下来。以后复检时，就能找出是哪一项变了。

## 七、红黄绿灯判定法

把五个维度的检查结果，归纳成三种颜色：

- 🟢 **绿灯**：可以用
- 🟡 **黄灯**：看业务场景，或补充其他检测后再决定
- 🔴 **红灯**：建议要求更换

| 维度 | 🟢 绿灯 | 🟡 黄灯 | 🔴 红灯 |
|---|---|---|---|
| ① 类型真实性 | 多数平台识别为住宅 / ISP | 平台之间有分歧（如 ping0 显示机房、其他显示 ISP） | 多数平台识别为机房 / 数据中心 |
| ② 地理一致性 | 国家一致，城市多数一致，原生 IP | 国家一致但城市分歧较大；或为广播 IP | 国家不一致 |
| ③ 历史信誉 | ping0 风控值 ≤ 25，IPQS 欺诈分 0–39 且 `recent_abuse=false` | ping0 风控值超过 25 分且不超过 50 分，或 IPQS 欺诈分 40–75，且未触发红灯 | ping0 风控值 > 50、IPQS 欺诈分 ≥ 76、查到近期滥用或多个来源都偏高 |
| ④ 独占性 | 共享人数显示 1–10，代理未检出。需要独享还得看购买条款 | 共享人数显示 10–100，或有平台标为住宅代理 | 共享人数显示 100–1000 或更高档，或多个来源识别为代理 / VPN |
| ⑤ 长期稳定性 | ASN、企业、注册地历史稳定 | 近期有一次变动 | 近期频繁变动 |

**使用说明**

1. **红黄绿灯是本系列的选购建议。** ping0 的说明把风控值分为 15 以内极度纯净、15–25 纯净、25–40 中性、40–50 轻微风险、50–70 稍高风险、70 以上极度风险。IPQS 网页把欺诈分分为 0–39 低风险、40–75 可疑、76–84 有风险、85–89 高风险、90–100 欺诈。它的 API 有另外的处理建议，见第 06 篇。
2. **黄灯要结合业务看**。比如，几家检测站查出的城市不一样。只要求国家一致的业务，可以先看国家是否对得上。要用某个城市，就去实际使用的平台核对（每类人群的具体标准见第 09、10 篇）。
3. **采购时先处理红灯**。例如查到近期滥用，或报告显示的国家不符合约定，就按买时说好的条件要求更换。

## 八、三个典型冲突案例

### 案例 1：ping0 显示"IDC 机房"，IPQS 显示 Residential

IPQS 的 `connection_type` 给的是连接类型，ping0 的「IP 类型」按它对网段用途的判断来标。这两项查到的结果可能不同。

**怎么判断**：
- 再看 ipinfo 的 ASN 类型、IP2Location 的 usage type 等，看多数怎么说；
- 看 ping0 的 ASN 历史和企业历史中的"首次出现"时间——刚发生变动的 IP 段，ping0 自己也说明可能存在识别误差；
- 如果你的客户或团队以 ping0 为准，这就是一个实际的业务约束，应该直接按 ping0 的结论选择。

### 案例 2：IPQS 分数偏高，Scamalytics 显示低风险

**原因**：两者的数据来源和模型不同，各自观察到的滥用事件也不同。

**怎么判断**：
- 先看 IPQS 的 `recent_abuse`。如果是 `true`，说明 IPQS 报告了近期确认的滥用，买之前按红灯处理；
- 如果是 `false`，再看 ping0 的风控值。只有一家的分数落在黄灯区间，就按业务要求决定。字段没显示时，先记作没查到。

### 案例 3：三个地理库给出三个不同的城市

**原因**：数据来源和更新时间不同；广播 IP 更容易出现这种情况。

**怎么判断**：
- 先看是不是广播 IP（ping0 的原生 / 广播标记）；
- 看三个城市是否在同一个都市圈内（如洛杉矶与其周边城市），如果是，对多数业务影响不大；
- 对本地业务和本地化测试人员，以目标平台自己显示的城市为最终依据；如果平台显示的城市不符合要求，就不适合你的业务。

## 九、主依据选 ping0 还是 IPQS？

日常检测中，一般会选一个平台作为主依据，另一个用来复核。怎么选，取决于你的业务约束：

| 选 ping0 作为主依据 | 选 IPQS 作为主依据 |
|---|---|
| 团队或客户习惯看 ping0（中文社区非常普遍） | 更关心海外风控评分体系的视角 |
| 需要看"实际用途"层面的家宽 / 机房判断 | 需要"近期滥用""代理识别"这类明确的是 / 否信号 |
| 需要原生 / 广播、共享人数、归属历史等信息 | 需要通过 API 批量检测并接入自己的流程 |

无论选哪个，都建议用另一个复核一次。

如果你已经确定了主依据，又不想从零开始一个个检测，可以直接从已经按这个平台指标筛选过的 IP 中挑选，例如 GetIPProxy 的[按 Ping0 风控值选购的纯净住宅代理](https://getipproxy.com/zh-cn/static-residential-proxies/clean-ips/)和[按 IPQualityScore 欺诈分选购的纯净住宅代理](https://getipproxy.com/zh-cn/static-residential-proxies/clean-ips/ipqualityscore/)。两个页面使用的评分来源和量表不同，结果不能互相换算；到手后，仍建议用本文的方法再交叉验证一次。

## 常见问题

**Q：有没有一个网站能一次看完所有信息？**
没有。即使是信息最全的综合检测站，也只是一个数据源的视角。综合检测站适合作为起点，但结论要交叉验证。

**Q：目标平台到底用的是哪家数据库？**
有的平台没有公开用哪家库。业务要看地区时，先查你实际用的平台显示什么。第三方报告可以帮你核对出口的风险记录。

**Q：检测结果一周前是绿灯，今天变黄了，要换 IP 吗？**
先确认是哪个维度、哪个平台变了。单一来源的小幅波动很常见；如果出现近期滥用记录，或多个来源同时恶化，再考虑更换。详见第 11 篇。
